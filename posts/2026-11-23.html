Taskwarrior for Beginners: A Command-Line To-Do List That Gets Out of Your Way

Published: Nov 23, 2026

Just heard this news that Microsoft is officially retiring its To Do apps next year. All To Do apps will stop working on June 30, 2027.

Honestly, I never used that app, so Microsoft's retirement notice slid right past me like a notification I swiped away. I'm a former Mac user who switched to Linux, and while poking around my shiny new setup, I stumbled upon a to-do app that lives entirely in the terminal.

Now, please welcome our main character of this post: Taskwarrior

Setting Up Taskwarrior

The latest stable release is Taskwarrior 3.5.0, released August 16, 2026. You can install it from your distribution's package manager or build it from source.

I highly recommend you to read this setup page of the official website to check out how to install it properly on your linux distro.

Mostly Used Operations:

Once Taskwarrior is installed and sitting happily on your PATH, you're ready for the fun part. Think of the commands below as your daily muscle memory in the making: a few keystrokes for adding a task, a glance at your list, and a satisfying done when you finish something. Let's start with the most basic move of all, adding your very first task.

Adding Your First Tasks

Adding a task is one command. Everything after task add becomes the description:

$ task add Buy milk
Created task 1.
$ task add Buy eggs
Created task 2.
$ task add Bake cake
Created task 3.

Taskwarrior assigns each task a number. You'll use that number to refer to the task later.

Viewing Your List

$ task list

ID Description
-- -----------
1  Buy milk
2  Buy eggs
3  Bake cake

3 tasks.

Finishing Tasks

When you finish a task, mark it done:

$ task 1 done
$ task 2 done
$ task list

ID Description
-- -----------
1  Bake cake

1 task.

Notice that "Bake cake" is now ID 1. Taskwarrior renumbers pending tasks as you complete them, so IDs are convenient for quick typing but aren't permanent. If you're scripting or referring to a task across sessions, use its UUID instead.

Adding Due Dates

Attributes go after the description, written as name:value. A due date is the most common:

$ task add Submit the report due:2026-12-01

You can also use relative dates like due:thursday or due:tomorrow, which keeps things simple for short-term work.

Recurring Tasks

This is where Taskwarrior starts to earn its place. Rent, subscriptions, and weekly reviews are easy to forget, and recurrence lets you set them once:

$ task add Pay the rent due:1st recur:monthly until:2015-03-31
Created task 123.

The recur: attribute accepts named intervals like monthly or weekly, and it also accepts durations. For example, recur:14days creates a task every two weeks.

One caution about the example above: the until: date is in the past, so Taskwarrior won't generate new instances. For a real recurring task, use a future date, or leave until: out entirely if the task should repeat indefinitely.

Editing Tasks

To change an existing task, put its ID before modify:

$ task 1 modify due:thursday

The ID matters here. If you write task modify things I want to modify due:thursday with no ID, Taskwarrior treats the words as a search filter and tries to match tasks whose descriptions contain them. That's a common beginner mistake, so get in the habit of giving an ID or a filter that clearly identifies the task.

To remove a due date, set the attribute to nothing:

$ task 12 modify due:

Finding What to Work On Next

Once you have more than a handful of tasks, the question becomes "what should I do now?" The next report answers it:

$ task next

It doesn't simply sort by due date. Taskwarrior calculates an urgency score for each task based on factors such as due date, priority, and how long the task has been waiting, then shows the most urgent ones first. Due dates and priorities carry real weight in that score, so setting them is how you steer the list.

Multi-Line Descriptions

Sometimes a task needs more than a few words. You can pass a quoted string that spans multiple lines:

$ task add "Five syllables here
> Seven more syllables there
> Are you happy now?"

The > at the start of each continuation line is your shell's prompt for an unfinished quoted string, not part of the text. Your shell passes the newlines through as part of the description. Multi-line descriptions are handy for quick notes, but keep most tasks to a single line so they stay readable in task list.

Deleting Tasks

To remove a task entirely:

$ task 1 delete

Taskwarrior will ask you to confirm before it deletes anything. Deleting is permanent from your list's point of view, so read the prompt before answering. If you only want to hide a task you've finished, done is the better choice, since it keeps a record of the work.

Where to Go from Here

You now have the core workflow: add, list, finish, modify, and delete, plus due dates, recurrence, and the next report. Taskwarrior has much more, including custom reports, filters, tags, projects, and sync across machines. Start with the commands above, use them for a week, and add more features as you need them.
